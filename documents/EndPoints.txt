# CondoSecure - Especificación de Endpoints (REQ/RES)

Formato: método, ruta, request body, responses por status code.
Convenciones generales (no se repiten en cada endpoint):
- Todo endpoint protegido requiere header `Authorization: Bearer <token>`.
- `401` = no autenticado (token ausente/inválido/expirado). `403` = autenticado pero sin permiso para ese módulo/rol.
- `500` siempre disponible como `{ msg: "Error interno" }`, se omite abajo para no repetir.
- IDs que identifican "quién hizo la acción" (`id_usuario`) se obtienen del token decodificado en el backend, **nunca** del body enviado por el front.

## 1. AuthController

### `AuthController.login()`
`POST /auth/login`
```
REQ:
{ correo_login: "xxx", password: "xxx" }

RES 200:
{
  token: "eyJhbGciOi...",
  usuario: {
    id_usuario: 12,
    id_persona: 5,
    nombres: "Cynthia",
    apellidos: "Artieda",
    foto: "url_o_null",
    rol: { id_rol: 2, nombre: "Presidenta" },
    modulos: ["Dashboard", "Usuarios", "Roles", "Auditoria", "Reportes"]
  }
}

RES 401: { msg: "Correo o contraseña incorrectos" }
RES 403: { msg: "Tu cuenta está pendiente de aprobación" }   // estado = PENDIENTE
RES 403: { msg: "Tu cuenta fue rechazada" }                   // estado = RECHAZADO
RES 403: { msg: "Tu cuenta está inactiva" }                   // estado = INACTIVO
```

### `AuthController.registro()`
`POST /auth/registro` (multipart/form-data)
```
REQ:
{ nombres, apellidos, ci_ruc, numero_vivienda, correo_login, password, foto? }

RES 201: { msg: "Solicitud enviada, en espera de aprobación" }
RES 400: { msg: "La vivienda #Casa no está registrada en el sistema" }
RES 409: { msg: "Ya existe una cuenta con ese correo" }
```

### `AuthController.recuperarPassword()`
`POST /auth/recuperar-password`
```
REQ: { correo_login: "xxx" }
RES 200: { msg: "Si el correo existe, se envió un link de recuperación" }
```
Nota: siempre responde 200 igual exista o no el correo (evita filtrar qué correos están registrados).

### `AuthController.resetPassword()`
`POST /auth/reset-password`
```
REQ: { token: "xxx", nueva_password: "xxx" }
RES 200: { msg: "Contraseña actualizada" }
RES 400: { msg: "Token inválido o expirado" }
```

### `AuthController.logout()`
`POST /auth/logout`
```
RES 200: { msg: "Sesión cerrada" }
```

## 2. UsuarioController

### `UsuarioController.listar()`
`GET /usuarios?search=&estado=activos|inactivos|todos`

```
{

```


`PUT /usuarios/:id`
```
REQ: { nombres?, apellidos?, correo?, telefono?, foto? }
RES 200: { msg: "Usuario actualizado" }
RES 404: { msg: "Usuario no encontrado" }
```

### `UsuarioController.cambiarEstado()`
`PATCH /usuarios/:id/estado`

## 8. AlicuotaController

### `AlicuotaController.listar()`
`GET /alicuotas?id_vivienda=&mes=&anio=&estado=`
```
RES 200: { data: [ { id_alicuota, numero_vivienda, mes, anio, valor_base, fecha_vencimiento, estado } ] }
```

### `AlicuotaController.detalle()`
`GET /alicuotas/:id`
```
RES 200: { id_alicuota, vivienda, mes, anio, valor_base, fecha_vencimiento, estado, multa? }
```

**Generación de alícuotas:** proceso automático (cron mensual). Para cada Vivienda activa, calcula `valor_base = (Presupuesto.total / 12) * Vivienda.porcentaje_alicuota`, crea el registro con `fecha_vencimiento` = día 10 del mes y `estado = PENDIENTE`. No se expone como endpoint público — vive en `jobs/generarAlicuotas.job.js`, no en el controlador.

### `AlicuotaController.listarPropias()`
`GET /alicuotas/mis-alicuotas`
```
RES 200: { data: [ { id_alicuota, mes, anio, valor_base, fecha_vencimiento, estado } ] }
```
Filtra automáticamente por la vivienda del Residente autenticado. Solo lectura.
