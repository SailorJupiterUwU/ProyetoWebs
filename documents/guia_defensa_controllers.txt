--------------------------------------------------------
1. OPTIONAL CHAINING  ?.
--------------------------------------------------------
Qué es:
  El operador ?. detiene la evaluación y devuelve
  undefined en lugar de lanzar un error si el objeto
  de la izquierda es null o undefined.

Dónde aparece:

  req.usuario?.id_usuario
  req.usuario?.id_modulo
  modulo?.id_modulo
  ultimoToken?.token
  usuarioEncontrado.rol?.modulos

Por qué se usa:
  req.usuario lo inyecta el middleware de autenticación.
  Si por algún motivo el middleware no se ejecutó (ruta
  mal configurada, error de orden), req.usuario sería
  undefined. Sin el ?, hacer req.usuario.id_usuario
  lanzaría "Cannot read properties of undefined" y
  caería el servidor. Con el ? simplemente queda
  undefined y la auditoría se registra sin id de usuario.

  Lo mismo con modulo?.id_modulo: se busca el módulo en
  la BD. Si no existe (tabla vacía, nombre distinto), la
  búsqueda devuelve null. El ? evita que null.id_modulo
  explote.

Ejemplo concreto (autenticacion.controller.js):
  await registrarAuditoria(
    req.usuario?.id_usuario,   // puede ser undefined si no hay sesión
    modulo?.id_modulo,         // puede ser null si no existe el módulo
    "Cierre de sesión",
    req.ip
  );

2. OR PARA VALOR POR DEFECTO  ||
--------------------------------------------------------
Qué es:
  Si el valor de la izquierda es falsy (null, undefined,
  0, "", false), devuelve el valor de la derecha.

Dónde aparece:

  descripcion || ""
  motivo_rechazo || "Solicitud no aprobada por la directiva"
  req.body.comprobante || null
  rubroIngreso ? rubroIngreso.id_rubro : 1
  Number(req.query.page) || 1
  Number(req.query.limit) || 10
  Number(ingresosMesSum) || 0

Ejemplos concretos:

  usuario.controller.js:
    usuario.motivo_rechazo = motivo_rechazo || "Solicitud no aprobada por la directiva";
    // Si no mandaron motivo, pone el texto por defecto.

  ingreso.controller.js:
    let page = Number(req.query.page) || 1;
    // req.query.page llega como string o undefined.
    // Number(undefined) = NaN, que es falsy, entonces queda 1.
    let offset = (page - 1) * limit;
    // offset = cuántos registros saltarse para la paginación.

  ingreso.controller.js:
    const comprobantePath = req.file ? req.file.filename : (req.body.comprobante || null);
    // Si multer capturó un archivo → usa el nombre del archivo.
    // Si no hubo archivo → usa lo que mandaron en el body.
    // Si tampoco mandaron nada en el body → null.

3. TERNARIO  condicion ? valorSiTrue : valorSiFalse
--------------------------------------------------------
Qué es:
  Versión corta de un if/else en una sola línea.

Dónde aparece (ejemplos):

  usuario.controller.js:
    nombres: u.persona ? u.persona.nombres : ""
    // Si el usuario tiene persona asociada, toma sus nombres.
    // Si no, cadena vacía.

    numero_vivienda: u.vivienda ? u.vivienda.numero : "Sin Asignar"
    // Si tiene vivienda, su número. Si no, texto "Sin Asignar".

    correo: usuario.persona ? usuario.persona.correo : usuario.correo_login
    // Prefiere el correo de Persona; si no existe, usa correo_login.

  ingreso.controller.js:
    total_pagado: totalPagadoNum > 0 ? totalPagadoNum : 50.00
    // Si el cálculo dio algo > 0, usa ese valor.
    // Si por algún motivo quedó en 0 (no mandaron alícuota ni multa),
    // pone un valor por defecto de 50.00.

    num_documento: ing.comprobante || `REC-${ing.id_ingreso}`
    // Si tiene comprobante guardado, lo usa.
    // Si no, genera un número de recibo automático tipo "REC-42".

5. COMPUTED PROPERTY NAMES  [Op.like], [Op.or], [Op.in], [Op.between]
--------------------------------------------------------
Qué es:
  Sequelize define operadores como símbolos (Op.like es
  Symbol(like)). Para usarlos como clave de un objeto
  se ponen entre corchetes []. Es la sintaxis de
  "computed property" de ES6.

Dónde aparece:

  usuario.controller.js:
    filtroPersona[Op.or] = [
      { nombres:   { [Op.like]: `%${search}%` } },
      { apellidos: { [Op.like]: `%${search}%` } },
      { ci_ruc:    { [Op.like]: `%${search}%` } }
    ];
    // Op.or: busca registros donde CUALQUIERA de las tres
    //   condiciones sea verdadera.
    // Op.like con % al inicio y al final: busca la palabra
    //   en cualquier posición del texto (contiene).

  autenticacion.controller.js:
    codigo: { [Op.like]: "RESIDENTE" }
    // Búsqueda insensible a mayúsculas en MySQL.

  usuario.controller.js:
    estado: { [Op.in]: ["ACTIVO", "RECHAZADO"] }
    // Op.in: equivale a SQL WHERE estado IN ('ACTIVO','RECHAZADO')

  ingreso.controller.js:
    fecha_pago: { [Op.between]: [new Date(fecha_inicio), new Date(fecha_fin)] }
    // Op.between: equivale a SQL WHERE fecha_pago BETWEEN x AND y

  usuario.controller.js:
    required: Object.keys(filtroPersona).length > 0
    // Object.keys() devuelve un array con las claves del objeto.
    // Si filtroPersona está vacío {}, length = 0 → required: false
    //   (OUTER JOIN: muestra usuarios aunque no haya texto que buscar)
    // Si tiene filtros, length > 0 → required: true
    //   (INNER JOIN: solo usuarios cuya Persona cumpla el filtro)

6. MÉTODOS DE SEQUELIZE NO OBVIOS
--------------------------------------------------------

findByPk(id)
  Busca un registro por su Primary Key (clave primaria).
  Equivale a: WHERE id_usuario = id (o el campo PK del modelo).
  Retorna null si no lo encuentra.

findOne({ where: {...} })
  Busca el PRIMER registro que cumpla la condición.
  Retorna null si no encuentra ninguno.

findAll({ where: {...}, include: [...] })
  Busca TODOS los registros que cumplan la condición.
  El "include" hace JOINs automáticos con otras tablas.

findAndCountAll({ ... })
  Como findAll pero también devuelve el total de registros
  que cumplen la condición (útil para paginación).
  Retorna: { rows: [...], count: N }

Ingreso.sum("total_pagado", { where: {...} })
  Hace un SQL SUM(total_pagado) con el filtro indicado.
  Retorna el número o null si no hay registros.

Alicuota.count({ where: {...} })
  Hace SQL COUNT(*) con el filtro. Retorna un número.

RolModulo.destroy({ where: { id_rol: id } })
  Borra TODOS los registros que cumplan la condición.
  Aquí: elimina todos los módulos del rol antes de
  reasignarlos. (Estrategia: borrar todo y recrear).

Ingreso.update({ estado: "PAGADO" }, { where: { id_alicuota } })
  Actualiza campos sin cargar el objeto primero.
  Primer argumento: qué cambiar.
  Segundo argumento: qué registros afectar.

order: [["fecha_pago", "DESC"]]
  Ordena los resultados. Es un array de arrays porque
  Sequelize permite ordenar por múltiples columnas.
  "DESC" = más reciente primero.

include con through: { attributes: [] }
  autenticacion.controller.js:
    include: [{
      model: Modulo,
      through: { attributes: [] }  // <-- esto
    }]
  En una relación muchos a muchos (Rol-Módulo a través
  de RolModulo), Sequelize por defecto incluye también
  los campos de la tabla intermedia (id_rol, id_modulo).
  Con attributes: [] le decimos que NO incluya esos
  campos extra, solo los del Módulo.

7. ASYNC / AWAIT Y TRY-CATCH
--------------------------------------------------------
Qué es:
  async: marca que una función puede hacer operaciones
         asíncronas (que "esperan" respuesta, como BD).
  await: pausa la ejecución hasta que la promesa resuelve.
  try/catch: si algo falla dentro del try (error de BD,
             error de red, etc.), el catch lo atrapa y
             responde con 500 en lugar de caerse el servidor.

Por qué TODO usa async/await:
  Las consultas a la base de datos (Sequelize) y el hash
  de bcrypt son operaciones que tardan tiempo. Sin async/
  await el código continuaría antes de tener la respuesta
  y devolvería datos incompletos o undefined.

Patrón estándar en todos los controllers:
  module.exports.algo = async (req, res) => {
    try {
      const resultado = await Modelo.findAll({...});
      return res.status(200).json({ data: resultado });
    } catch (err) {
      console.error("Error:", err);
      return res.status(500).json({ msg: "Error interno", error: err.message });
    }
  };

9. BCRYPT — HASH DE CONTRASEÑAS
--------------------------------------------------------
  const salt = await bcrypt.genSalt(10);
  // Genera un "salt": datos aleatorios que se mezclan
  // con la contraseña antes de hashear. El 10 es el
  // "cost factor": cuántas rondas de procesamiento.
  // Más alto = más seguro pero más lento.

  const hashedPassword = await bcrypt.hash(password, salt);
  // Combina la contraseña con el salt y la hashea.
  // El resultado nunca se puede revertir (no hay descifrado).

  const esPasswordValido = await bcrypt.compare(password, usuarioEncontrado.password_hash);
  // Vuelve a hashear "password" con el salt que está
  // guardado dentro de password_hash y compara.
  // Devuelve true/false.
  // Por eso nunca guardamos la contraseña en texto plano.

10. JWT — JSON WEB TOKEN
--------------------------------------------------------
  const generateToken = (id_usuario, id_rol, rolNombre) => {
    return JWT.sign(
      { id_usuario, id_rol, rol: rolNombre },  // payload (datos que viajan en el token)
      JWT_SECRET,                               // clave secreta para firmarlo
      { expiresIn: JWT_EXPIRES_IN }             // cuánto tiempo es válido
    );
  };
  // El token resultante tiene 3 partes separadas por punto:
  //   header.payload.firma
  // No está cifrado, pero está firmado: si alguien lo
  // modifica, la firma no coincide y el servidor lo rechaza.

  JWT.verify(token, JWT_SECRET)
  // En el middleware: verifica que la firma sea válida y
  // que no haya expirado. Si algo falla, lanza una excepción
  // que el catch devuelve como 401.

16. ESTRATEGIA BORRAR-Y-RECREAR EN PERMISOS
--------------------------------------------------------
  rol.controller.js (actualizarModulos):
    // 1. Eliminar las asignaciones anteriores de este rol
    await RolModulo.destroy({ where: { id_rol: id } });

    // 2. Insertar las nuevas asignaciones
    for (let i = 0; i < modulos.length; i++) {
      await RolModulo.create({ id_rol: id, id_modulo: modulos[i] });
    }

  Por qué así y no actualizando uno por uno:
    Es más simple. En lugar de detectar qué módulos se
    agregaron, cuáles se quitaron y cuáles no cambiaron,
    se borran todos y se insertan los nuevos desde cero.
    La desventaja es que si el create falla a la mitad,
    quedan permisos incompletos (no hay transacción).

17. if (condicion !== undefined) vs if (condicion)
--------------------------------------------------------
  usuario.controller.js (editar):

    if (telefono !== undefined) usuario.persona.telefono = telefono;

21. NULLISH COALESCING  ??
--------------------------------------------------------
Qué es:
  Similar al ||, PERO solo activa el valor de la derecha
  si el de la izquierda es exactamente null o undefined.
  Con || también se activa si es 0, "", o false.

Dónde aparece (auditoria.controller.js):
  rol_nombre:    a.usuario?.rol?.nombre ?? "N/A",
  modulo_nombre: a.modulo?.nombre       ?? "General",

Por qué importa la diferencia con ||:
  Si nombre = "" (cadena vacía), con || daría "N/A".
  Con ?? dejaría la cadena vacía tal cual, porque ""
  no es null ni undefined. Es más preciso.

Doble optional chaining encadenado:
  a.usuario?.rol?.nombre
  // Primero verifica que usuario no sea null/undefined,
  // luego verifica que rol no sea null/undefined,
  // finalmente accede a nombre.
  // Si cualquiera del medio es null → undefined (no error).

22. .map() PARA TRANSFORMAR RESPUESTA (auditoria.controller.js)
--------------------------------------------------------
  const data = auditoriasBDD.map((a) => ({
    fecha: a.fecha,
    usuario_nombre: a.usuario?.persona
      ? `${a.usuario.persona.nombres} ${a.usuario.persona.apellidos}`
      : "Sistema",
    rol_nombre:    a.usuario?.rol?.nombre ?? "N/A",
    modulo_nombre: a.modulo?.nombre       ?? "General",
    accion:        a.accion,
  }));

  Es el fragmento más denso del proyecto. En una sola
  expresión combina:
  - .map() para transformar cada registro
  - optional chaining (?.)
  - ternario para nombre completo vs "Sistema"
  - template literal para concatenar nombre + apellido
  - nullish coalescing (??) para valores por defecto

  La flecha devuelve un objeto: () => ({...})
  Los paréntesis extra son necesarios para que JS no
  confunda las llaves {} del objeto con las llaves del
  cuerpo de la función.

23. FILTRO where CONDICIONAL CON Object.keys().length
--------------------------------------------------------
  auditoria.controller.js:
    where: Object.keys(whereUsuario).length ? whereUsuario : undefined,

  Object.keys(objeto) → devuelve array con las claves.
  Si el objeto está vacío {}, .length = 0 → falsy → undefined.
  Si tiene algo, .length > 0 → truthy → usa el filtro.

  Cuando Sequelize recibe where: undefined en un include,
  lo ignora completamente (LEFT JOIN sin filtro).
  Si recibe where: { algo: valor }, aplica el filtro
  (y fuerza INNER JOIN si required:true).

--------------------------------------------------------
24. WHERE con Op.gte, Op.lte, Op.lt
--------------------------------------------------------
  auditoria.controller.js:
    { [Op.between]: [new Date(fecha_inicio), new Date(`${fecha_fin}T23:59:59`)] }
    { [Op.gte]: new Date(fecha_inicio) }   // mayor o igual que
    { [Op.lte]: new Date(fecha_fin+"T23:59:59") } // menor o igual que

  egreso.controller.js:
    { [Op.lt]: hoy }   // menor que (less than)

  El template literal `${fecha_fin}T23:59:59` agrega
  la hora al final del día. Sin esto, al filtrar hasta
  "2025-03-10" solo incluiría hasta las 00:00:00 de ese
  día, excluyendo todo el resto del día.

  Op.gte = >= (greater than or equal)
  Op.lte = <= (less than or equal)
  Op.lt  = <  (less than)
  Op.gt  = >  (greater than)

--------------------------------------------------------
25. .sort() CON COMPARADOR DE FECHAS
--------------------------------------------------------
  dashboard.controller.js y historial.controller.js:
    movimientos.sort((a, b) => new Date(b.fecha) - new Date(a.fecha));

  sort() sin argumento ordena como texto (mal para números/fechas).
  Con la función comparadora:
  - Si b > a: resultado positivo → b va antes (DESC)
  - Si a > b: resultado negativo → a va antes
  - Si son iguales: 0 → no cambia el orden

  new Date("2025-01-10") - new Date("2025-01-05")
  → positivo → 2025-01-10 va primero → orden descendente.

26. .slice() PARA RECORTAR ARRAY
--------------------------------------------------------
  dashboard.controller.js:
    let data = movimientos.slice(0, limit);

  .slice(inicio, fin) — extrae un subarray.
  No modifica el array original (no destructivo).
  Aquí: toma los primeros `limit` elementos.
  Diferente a .splice() que SÍ modifica el original.

27. Math.floor(Math.random() * rango) + base
--------------------------------------------------------
  dashboard.controller.js:
    ingresos: Math.floor(Math.random() * 2000) + 3000,
    egresos:  Math.floor(Math.random() * 2000) + 2500

  Math.random() → decimal entre [0, 1)
  * 2000 → decimal entre [0, 2000)
  Math.floor() → entero entre [0, 1999]
  + 3000 → entero entre [3000, 4999]

  Son datos simulados para el gráfico del dashboard.
  En producción real se reemplazarían por consultas reales.

    const [rubroEnBD] = await Rubro.findOrCreate({
      where:    { nombre: rubroExcel.nombre },
      defaults: { codigo: codigoGenerado, nombre: rubroExcel.nombre, tipo: "EGRESO" }
    });

  Retorna un array de dos elementos: [instancia, created]
  - instancia: el registro encontrado o recién creado
  - created: boolean (true si fue creado, false si ya existía)

  La desestructuración [rubroEnBD] toma solo el primer
  elemento. El segundo (created) se ignora porque no
  se necesita saber si fue nuevo o no.

  where: la condición para buscar.
  defaults: campos a usar solo si se va a CREAR (no aplican
            en la búsqueda, solo en el INSERT).

29. upsert() — INSERTAR O ACTUALIZAR
--------------------------------------------------------
  presupuesto.controller.js:
    await PresupuestoRubro.upsert({
      id_presupuesto: nuevoPresupuesto.id_presupuesto,
      id_rubro:       rubroEnBD.id_rubro,
      monto_asignado: rubroExcel.total
    });

  upsert = UPDATE if exists + INSERT if not.
  Sequelize detecta si ya existe el registro usando las
  claves únicas definidas en el modelo.
  Si existe → UPDATE. Si no → INSERT.
  Más eficiente que hacer findOne + create/update.

30. REGEX EN replace()
--------------------------------------------------------
  presupuesto.controller.js:
    rubroExcel.nombre.replace(/\s+/g, "").substring(0, 14).toUpperCase()

  /\s+/g → expresión regular:
  - \s  → cualquier espacio en blanco (espacio, tab, salto de línea)
  - +   → uno o más consecutivos
  - /g  → flag "global": reemplaza TODOS, no solo el primero

  Sin /g solo reemplazaría el primer espacio.
  Con /g reemplaza todos.

  .substring(0, 14) → toma los primeros 14 caracteres.
  .toUpperCase()    → convierte a mayúsculas.

  Resultado: "Mantenimiento General" → "MantenimientoG" → "MANTENIMIENTOG"

31. .toISOString().split("T")[0]
--------------------------------------------------------
  presupuesto.controller.js:
    fecha_vencimiento: fechaVenc.toISOString().split("T")[0],

  fechaVenc.toISOString() → "2025-03-10T00:00:00.000Z"

32. REDONDEO A 2 DECIMALES
--------------------------------------------------------
  presupuesto.controller.js:
    const valorMensual = Math.round((totalFinal * porcentaje / 12) * 100) / 100;

  No se puede hacer Math.round() directamente porque
  Math.round(12.346) = 12 (redondea al entero).

  Truco: multiplicar por 100, redondear al entero,
  dividir entre 100.
  Math.round(12.346 * 100) / 100
  = Math.round(1234.6) / 100
  = 1235 / 100
  = 12.35

  .toFixed(2) también da 2 decimales pero retorna STRING.
  Este método retorna NUMBER.

33. for...of CON await (vs forEach)
--------------------------------------------------------
  presupuesto.controller.js:
    for (const rubroExcel of rubrosDelExcel) {
      await Rubro.findOrCreate(...);  // funciona
    }

  Por qué NO se puede usar forEach con await:
    rubrosDelExcel.forEach(async (rubro) => {
      await Rubro.findOrCreate(...);  // NO espera entre iteraciones
    });
  forEach no espera las promesas. Lanzaría todas las
  consultas en paralelo y sin orden garantizado.

  for...of SÍ espera cada await antes de continuar con
  el siguiente elemento. Permite procesamiento secuencial.

  También se puede usar continue dentro de for...of:
    if (!porcentaje || porcentaje <= 0) continue;  // salta esta iteración

36. as: ALIAS EN include DE SEQUELIZE
--------------------------------------------------------
  visitante.controller.js y qr.controller.js:
    include: [{ model: Vivienda, as: "viviendaDestino" }]

  ¿Por qué el alias?
  En el modelo Visitante, la relación con Vivienda se
  definió con un alias específico (as: "viviendaDestino")
  porque puede haber varias relaciones entre los mismos
  modelos. Sin el alias, Sequelize no sabe qué asociación
  usar y lanza error.

  Al acceder al resultado:
    visitante.viviendaDestino.numero  // con el alias
    // No: visitante.vivienda.numero  (ese nombre no existe)

37. Array.isArray() PARA VALIDAR TIPO
--------------------------------------------------------
  rol.controller.js:
    if (modulos && Array.isArray(modulos)) {
      for (let i = 0; i < modulos.length; i++) { ... }
    }

  Doble validación:
  1. modulos → que no sea null/undefined (falsy)
  2. Array.isArray(modulos) → que sea realmente un array

  ¿Por qué no solo if (modulos)?
  Si el cliente manda modulos como un número o string,
  sería truthy pero .length o el for fallarían.
  Array.isArray() garantiza que sea iterable como array.

  typeof no sirve para arrays porque typeof [] = "object".
  Por eso existe Array.isArray().

38. CONDICIÓN DE NEGOCIO: VEHÍCULO SIN PLACA
--------------------------------------------------------
  visitante.controller.js:
    if (tiene_vehiculo && !placa) {
      return res.status(400).json({ msg: "Debe indicar la placa si el visitante tiene vehículo" });
    }

  tiene_vehiculo && !placa:
  Solo falla si AMBAS se cumplen:
  - tiene_vehiculo es truthy (mandaron true)
  - Y placa es falsy (no mandaron placa)

  Si tiene_vehiculo es false → la condición completa
  es false (short-circuit) y no entra al if.
  Si placa está presente → !placa es false → no entra.

  Es una regla de negocio: vehículo implica placa obligatoria.
